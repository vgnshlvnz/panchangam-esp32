# X post format

Implemented by `panch_format_x()` in `core/format.c`; the Python reference is
`format_x()` in `tools/gen_format_cases.py`. The host test requires the two to
match byte for byte for 30 reference dates, and checks the length for all 750.

## Layout

```
🌙 Panchangam 2026-09-19, Shanivara
Sunrise 07:03 Sunset 19:10
Tithi: Shukla Ashtami 15:31-17:57, Shukla Navami 17:57-20:22
Nakshatra: Mula 01:14-04:13, Purva Ashadha 04:13-07:04
Yoga: Ayushman 16:04-16:59, Saubhagya 16:59-17:52
Karana: Bava 04:43-17:57, Balava 17:57-07:10
```

- Line 1: moon emoji, `Panchangam`, ISO date, comma, vara name.
- Line 2: `Sunrise HH:MM Sunset HH:MM`.
- One line each for Tithi, Nakshatra, Yoga, Karana: `Label: ` then the spans
  in time order, separated by `, `, each `Name HH:MM-HH:MM`.
- Times are local (MYT, UTC+8), 24-hour, whole minutes, from the JD rounded to
  the nearest second. No trailing newline.
- Names are Latin transliteration from `core/names.h` (generated by
  `tools/gen_names.py`).

## Length

- Limit: 280 weighted characters (`PANCH_X_MAX_WEIGHT`). Latin letters, digits,
  punctuation and newline weigh 1; the emoji weighs 2 (twitter-text rules).
- If the full text is too long, the Karana line is dropped, then the Yoga line.
  Whole lines are dropped; a field is never cut in half.
- If it still does not fit, `panch_format_x()` returns `PANCH_ERR_CAPACITY` and
  the firmware skips X. Across the 750 reference dates this never happens
  (678 need karana dropped, 2 need karana and yoga dropped).

## No links

The text never contains a URL.
